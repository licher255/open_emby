emby-engine — 原生生成引擎（Rust）

借鉴 ComfyUI 后端架构、用 Rust 重写的节点图执行引擎，替代「App → 外部 ComfyUI 进程」的旧链路。 位置 crates/emby-engine，由 Electron 主进程拉起，仅监听 127.0.0.1:8189。

01为什么

旧链路 Electron → ComfyUI(8188) 依赖外部 Python 进程：启动慢、分发重 （模型运行时 + 依赖数百 MB），且 img2img 扩散对「制版平涂」这一步既慢又不可控。新引擎：

  • 纯 Rust 单二进制 — 无 Python 运行时，随 App 分发，启动毫秒级。
  • API 与 ComfyUI 对齐 — /prompt /queue /history /view /upload/image /object_info /ws； 工作流 JSON 格式（{id: {class_type, inputs}} + [node, slot] 链接）完全一致， 生态工具可复用，未来节点迁移零成本。
  • 制版领域原生节点 — EmbyColorBlockStylize 用 Lab KMeans 做限色平涂， 毫秒级、限色精确、结果可复现，比扩散模型更贴合刺绣色块分离的真实需求。

04路线图：扩散推理原生落地（candle）

  1. candle 后端 — 引入 candle-core / candle-transformers，SD1.5 / SD-Turbo 起步 （UNet + CLIP + VAE），Value::Handle 占位类型承载真实权重；Safetensors 直读。
  2. 采样器 — euler / DDIM 起步（sampler_name / scheduler 枚举已对齐），逐步补齐 k_diffusion 常用项。
  3. LoRA — 在 LoraLoader 节点做权重合并（candle varbuilder 层操作）。
  4. 设备 — CPU 先行（制版场景图小、可接受），CUDA feature 可选编译。
  5. 显存管理 — 对应 ComfyUI 的 model management，按缓存键 LRU 卸载句柄。

06运维

# cargo build --release（setup 已包含）
pnpm run engine:build
# cargo run（调试用，默认 127.0.0.1:8189）
pnpm run engine:dev

主进程启动时自动拉起（src/main/services/engine.ts），退出时整棵进程树回收。 App 设置项 engineUrl 可改地址；引擎目录为 <数据根>/engine/。
